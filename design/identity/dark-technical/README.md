# Dark / Technical

Use this recipe when dense information and precise control are central to the experience. Express it through crisp hierarchy, carefully limited accent color, data legibility, and concise copy. Keep standard platform controls recognizable.

Dark-first is a brand direction, not permission to ignore system appearance or accessibility. Before implementation, define semantic colors for every applicable appearance and increased contrast, readable type, focus states, motion, and a Reduce Motion equivalent.

## Working grammar

- **Hierarchy:** Group data by the decision it supports. Give the current status and primary control a clear place even when many values are visible.
- **Color:** Use a limited semantic palette for status and selection. Never make color the only way to distinguish a warning, active state, or value.
- **Typography:** Use tabular figures where comparison matters and readable text styles for explanations. Check long labels and localization before compressing columns.
- **Motion:** Use restrained transitions to show cause and effect or changes in data. Keep a stable view for monitoring and a Reduce Motion path.
- **Control:** Make precise actions, undo, keyboard focus, pointer targets, and destructive confirmation easy to discover through native platform behavior.

## Review in a real app

Inspect a dense screen, an empty screen, and an error with real data. Check contrast in light and dark appearances, distinction between adjacent status colors, focus visibility, and legibility on compact hardware. Record evidence in `docs/design/NATIVE-REVIEW.md`.
